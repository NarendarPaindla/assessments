# 2. Theory

---

## What is a Migration File?

A migration file is a Python script that describes database changes.

Example:

Today:

```python
class User(Base):
    id = Column(Integer, primary_key=True)
    name = Column(String)
```

Tomorrow:

```python
class User(Base):
    id = Column(Integer, primary_key=True)
    name = Column(String)
    phone = Column(String)
```

Alembic detects the difference and generates a migration.

---

## Migration Lifecycle

```text
Models Changed
      ↓
alembic revision --autogenerate
      ↓
Migration File Created
      ↓
alembic upgrade head
      ↓
Database Updated
```

---

## What is Autogenerate?

Instead of writing SQL manually:

```sql
CREATE TABLE users (...);
CREATE TABLE products (...);
```

Alembic reads:

```python
User
Category
Product
Cart
CartItem
Order
OrderItem
```

and generates migration code automatically.

# 5. Generated Migration File

Alembic creates something similar to:

```python
from alembic import op
import sqlalchemy as sa


revision = "abc123"
down_revision = None
branch_labels = None
depends_on = None


def upgrade():

    op.create_table(
        "users",

        sa.Column(
            "id",
            sa.Integer(),
            nullable=False
        ),

        sa.Column(
            "name",
            sa.String(),
            nullable=False
        ),

        sa.Column(
            "email",
            sa.String(),
            nullable=False
        ),

        sa.PrimaryKeyConstraint("id")
    )


def downgrade():

    op.drop_table("users")
```

Your file will be much larger because we have 7 tables.

Do NOT edit it manually.

# 6. Explanation

---

## Revision ID

Example:

```python
revision = "abc123"
```

Unique migration identifier.

Think:

```text
Version Number
```

---

## down_revision

```python
down_revision = None
```

Means:

```text
First Migration
```

Future migrations:

```python
down_revision = "abc123"
```

will point to previous migration.

---

## upgrade()

```python
def upgrade():
```

Contains instructions to move database forward.

Example:

```python
op.create_table(...)
```

---

When running:

```bash
alembic upgrade head
```

Alembic executes:

```python
upgrade()
```

---

## downgrade()

```python
def downgrade():
```

Contains reverse operations.

Example:

```python
op.drop_table(...)
```

---

When running:

```bash
alembic downgrade
```

Alembic executes:

```python
downgrade()
```

---

# Internal Flow

Alembic:

```text
Read Models
      ↓
Compare Database
      ↓
Database Empty
      ↓
Generate CREATE TABLE Commands
      ↓
Store in Migration File
```

# 10. Common Errors

---

## Error 1

```text
No changes detected
```

Reason:

Models not imported.

Check:

```python
import app.models
```

inside:

```text
alembic/env.py
```

---

## Error 2

```text
Target database is not up to date
```

Usually occurs when migration history exists.

Delete old DB and regenerate.

---

## Error 3

```text
No module named app
```

Run command from:

```text
ecommerce_backend/
```

root folder.

---

## Error 4

```text
Can't locate revision
```

Migration files corrupted.

Delete migration and regenerate.

---

## Error 5

```text
Migration generated but empty
```

Reason:

```python
target_metadata = Base.metadata
```

missing.
