# 2. Theory

## What is a Database?

A database is a place where data is stored permanently.

Without a database:

```python
users = [
    {"name": "Narendar"}
]
```

Problem:

When server stops:

```text
❌ Data Lost
```

---

With a database:

```text
Server Stop
Server Start

✅ Data Still Exists
```

---

## Real World Example

Think about Amazon.

Amazon stores:

```text
Users
Products
Categories
Orders
Payments
Cart Items
```

Where?

Inside a database.

---

## What is SQLite?

SQLite is a lightweight database.

Unlike MySQL or PostgreSQL:

```text
MySQL
 └── Separate Server

PostgreSQL
 └── Separate Server
```

SQLite:

```text
Single File
```

Example:

```text
ecommerce.db
```

Everything is stored in one file.

---

## Why SQLite?

For learning FastAPI:

✅ Easy

✅ No installation

✅ Lightweight

✅ Perfect for development

Later you can move to:

* PostgreSQL
* MySQL
* SQL Server

without changing much code.

# Rows

Rows are actual records.

Example:

| id | name     |
| -- | -------- |
| 1  | Narendar |

One row = one user.

---

# Primary Key

Every table needs a unique identifier.

Example:

| id | name     |
| -- | -------- |
| 1  | Narendar |
| 2  | Ravi     |

Column:

```text
id
```

is the Primary Key.

---

Primary Key Rules:

✅ Unique

✅ Cannot be NULL

✅ Identifies a record

---

Bad:

| id | name  |
| -- | ----- |
| 1  | Ravi  |
| 1  | Kumar |

Duplicate IDs.

❌ Not allowed.

---

# Foreign Key

Foreign Key connects tables.

Example:

Category Table

| id | name        |
| -- | ----------- |
| 1  | Electronics |

---

Products Table

| id | name   | category_id |
| -- | ------ | ----------- |
| 1  | Laptop | 1           |

category_id points to:

```text
Category.id
```

This is a Foreign Key.

---

# Relationships

## One To Many

One Category

Many Products

Example:

```text
Electronics
    ├── Laptop
    ├── Mobile
    └── TV
```

Database:

```text
Category
   ↓
Products
```

---

## One User → Many Orders

```text

   ├── Order1
```

# 5. Explanation

### Why Not Store Everything in One Table?

Bad Design:

```text
Product
User
Order
Cart

All in one table
```

Problems:

* Duplicate data
* Slow queries
* Difficult maintenance

---

Good Design:

```text
User
Category
Product
Cart
CartItem
Order
OrderItem
```

Each table has one responsibility.

# 9. Common Beginner Mistakes

---

## Mistake 1

Thinking SQLite is Python.

Wrong:

```text
SQLite = Python
```

Correct:

```text
SQLite = Database
Python = Programming Language
```

---

## Mistake 2

Using duplicate primary keys.

Wrong:

```text
1
1
1
```

Correct:

```text
1
2
3
```

---

## Mistake 3

Not using relationships.

Wrong:

```text
Product stores category name directly
```

Correct:

```text
Product stores category_id
```

---

## Mistake 4

Storing passwords in plain text.

Wrong:

```text
123456
```

Correct:

```text
hashed_password
```

(We'll implement hashing in Authentication Phase.)
