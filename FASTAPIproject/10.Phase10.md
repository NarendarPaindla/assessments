Instead they use **Alembic Migrations**.

# 2. Theory

---

## Problem with create_all()

Imagine:

Today:

```python
class User(Base):
    id
    name
```

Database:

```sql
users
 ├── id
 └── name
```

---

Tomorrow:

```python
class User(Base):
    id
    name
    phone
```

You restart application.

Question:

```text
Will SQLite automatically add phone column?
```

Answer:

```text
❌ No
```

`create_all()` only creates missing tables.

It does NOT safely modify existing tables.

---

## What is a Migration?

Migration = Database Change History

Example:

```text
Version 1
 └── Create users table

Version 2
 └── Add phone column

Version 3
 └── Add products table

Version 4
 └── Add orders table
```

Each change becomes a migration file.

---

## What is Alembic?

Alembic is SQLAlchemy's migration tool.

It helps:

✅ Create migrations

✅ Track schema changes

✅ Upgrade database

✅ Downgrade database

✅ Maintain history

---

## Real Company Workflow

Developer changes model:

```python
email = Column(String)
```

Then:

```bash
alembic revision --autogenerate
```

Alembic creates migration.

Then:

```bash
alembic upgrade head
```

Database updates.

# Final env.py Changes

Important part should look like:

```python
from logging.config import fileConfig

from sqlalchemy import engine_from_config
from sqlalchemy import pool

from alembic import context

from app.database import Base

import app.models

config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata
```

# 5. Explanation

---

## Why Change target_metadata?

Alembic needs access to models.

Without:

```python
target_metadata = Base.metadata
```

Alembic cannot see:

```text
User
Category
Product
Cart
Order
```

tables.

---

## Why Import app.models?

Remember:

```python
class User(Base):
```

only exists after importing.

Without:

```python
import app.models
```

Alembic sees:

```text
No Tables
```

---

## Why Remove create_all()?

Bad:

```python
create_all()
```

Professional:

```bash
alembic upgrade head
```

Reason:

```text
Migration History
Schema Tracking
Rollback Support
Production Safe
```

---

# Internal Flow

Alembic:

```text
Read Models
      ↓
Compare Database
      ↓
Generate Migration
      ↓
Upgrade Database
```
